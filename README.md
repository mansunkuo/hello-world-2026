# Structurizr Template

A project template for modelling software architecture as code with [Structurizr](https://structurizr.com)
(the [C4 model](https://c4model.com)), with:

- local development using **Docker** or **Podman** (via the container CLI directly), and
- a **GitHub Action** that exports an interactive static site and publishes it to **GitHub Pages**.

See the [Structurizr static site documentation](https://docs.structurizr.com/export/static-site) for details
on what the static export supports.

> The container image used throughout this template is `structurizr/structurizr`, which bundles the
> consolidated Structurizr tooling (`local`, `validate`, `export`, etc.). The standalone `structurizr/cli`
> image is deprecated.

## Project structure

```
.
├── Makefile                          # Forwards make targets to structurizr/Makefile
├── structurizr/                      # Structurizr workspace (the "as code" source of truth)
│   ├── workspace.dsl                 # C4 model and views in Structurizr DSL
│   ├── workspace.json                # Generated by Structurizr local; keeps manual diagram layout
│   └── Makefile                      # Convenience targets for Docker/Podman
└── .github/
    └── workflows/
        └── deploy-static-site.yml    # Exports the static site and deploys it to GitHub Pages
```

## Prerequisites

- [Docker](https://www.docker.com/) or [Podman](https://podman.io/)

Both runtimes accept the same commands; the README shows Docker first, swap `docker` for `podman` to use
Podman. All commands run from the project root.

## Local development

### 1. View and edit the workspace interactively (Structurizr local)

```bash
docker run -it --rm --user "$(id -u):$(id -g)" \
  -p 8080:8080 -v "$PWD/structurizr:/usr/local/structurizr" \
  structurizr/structurizr local
```

Then open <http://localhost:8080>. The container watches `workspace.dsl`; edit the file and refresh to see
changes. Manual layout tweaks are saved to `workspace.json` (commit it to keep your layout).

Or detached, with logs on demand:

```bash
docker run -d --rm --name structurizr --user "$(id -u):$(id -g)" \
  -p 8080:8080 -v "$PWD/structurizr:/usr/local/structurizr" \
  structurizr/structurizr local
docker logs -f structurizr      # tail logs
docker stop structurizr          # stop
```

The `--user "$(id -u):$(id -g)"` flag makes container-created files (e.g. `workspace.json`) owned by your
local user instead of root. You can drop it on macOS/Windows Docker Desktop.

### 2. Validate the workspace

```bash
docker run --rm --user "$(id -u):$(id -g)" \
  -v "$PWD/structurizr:/usr/local/structurizr" \
  structurizr/structurizr validate -workspace workspace.dsl
```

### 3. Export the static site locally

```bash
mkdir -p structurizr/static-site
docker run --rm --user "$(id -u):$(id -g)" \
  -v "$PWD/structurizr:/usr/local/structurizr" \
  structurizr/structurizr export -workspace workspace.dsl -format static -output static-site
```

This writes an interactive site (diagram navigation, zoom, diagram key, etc.) to `structurizr/static-site/`.
Preview it locally with:

```bash
python3 -m http.server 8080 --directory structurizr/static-site
```

To export with manually saved layout instead (from `workspace.json`, which retains layout created in
Structurizr local), point `-workspace workspace.json` instead.

### Make targets

Run from the project root (the root `Makefile` forwards to `structurizr/`):

```bash
make up            # start the interactive viewer detached (http://localhost:8080)
make down          # stop the viewer container
make logs          # follow the viewer logs
make export        # export the static site to structurizr/static-site/
make validate      # validate workspace.dsl
make clean         # remove the exported structurizr/static-site/
```

By default the Makefile uses Docker. To use Podman, override `DOCKER`:

```bash
DOCKER=podman make up
DOCKER=podman make export
```

## GitHub Pages

The workflow in `.github/workflows/deploy-static-site.yml`:

1. runs on every push to `main` (or via `workflow_dispatch`)
2. runs the `structurizr/structurizr` Docker image to export `structurizr/workspace.dsl` as a static site
3. uploads the result as a GitHub Pages artifact and deploys it via `actions/deploy-pages`

### One-time setup

1. Push this template to a GitHub repository.
2. In the repository: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Trigger the workflow (`Push` to `main`, or **Actions → "Build and publish Structurizr static site → Run workflow"**).

The static site is then published at `https://<owner>.github.io/<repo>/` (project site) or
`https://<owner>.github.io/` (user/organisation site).
